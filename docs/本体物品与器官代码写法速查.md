## 一、四层 priority 骨架

| 层 | priority | 位置 | 职责 |
|---|---|---|---|
| 工具层 | 3000 | `server_scripts/util/organ.js` | 全局函数（KV、槽位类型、冷却、音效） |
| 模型层 | 2000 | `server_scripts/model/**` | `OrganStrategyModel` / `OrganItemModel` / `OrganEventModel` |

文件首行固定写 `// priority: 500`（无分号、无引号）。

## 二、物品注册（startup）

```js
// priority: 500
StartupEvents.registry('item', event => {
    event.create('kubejs:sea_bunny_skin')
        .food(food => food.hunger(1).saturation(0.5))        // 可选：能吃
        .maxStackSize(1)
        .texture('kubejs:item/organs/nature/sea_bunny_skin') // 贴图路径 = 物品路径镜像
        .tag('kubejs:nature')                                // 分类标签（必填）
        .tag('kubejs:muscle')                                // 可选：部位标签

    // 带负面效果的食物
    event.create('kubejs:spider_leg')
        .food(food => food.hunger(2).saturation(0.5).effect('minecraft:poison', 200, 0, 0.5))
        .maxStackSize(1)
        .texture('kubejs:item/organs/nature/spider_leg')
        .tag('kubejs:nature').tag('kubejs:muscle')
})
```

约定：
- 一个分类一个文件（`nature.js`、`machine.js`…），全部塞进同一个 `StartupEvents.registry('item', ...)` 块
- `.tag()` 链式连续写，不换行拆开
- 主动技能器官额外 `.tag('kubejs:key_active')` —— 框架靠 `IsItemNeedKeyActive` 读这个标签

## 三、器官数据（server，priority 500）

```js
RegistryOrgan('kubejs:cindaria_umbrella')
    .addScore('chestcavity:detoxification', 1)
    .addScore('chestcavity:defense', -1)     // 支持负分
    .setCanSpawn(true)                       // 允许自然生成在生物胸腔里
```

- 伪器官（不在物品栏、只靠脚本塞进去的）：`RegistryPseudoOrgan('id')`
- **不需要手写数据 JSON**：`organ_item_model.js` 里的 `ServerEvents.highPriorityData` 会自动生成
  `kubejs:organs/kubejs/<物品名>.json` = `{itemID, pseudoOrgan, organScores}`
- 同时自动打 `kubejs:organ` 标签；`.setCanSpawn(true)` 的再进 `kubejs:spawn_in_cavity`
- 合法分数共 40 个，见 `$ScoreType` 常量链（`chestcavity:*` 22 个 + `kubejs:*` 18 个）

## 四、策略登记（server，文件末尾）

```js
RegistryOrganStrategy(
    new OrganStrategyModel('kubejs:blaze_spine')
        .addOnlyStrategy('entity_do_damage', BlazeSpineEntityDoDamage)
        .addOnlyStrategy('key_active', BlazeSpineKeyActiveOnly)
        .addOnlyStrategy('organ_take_off', BlazeSpineOrganTakeOff)
)
```

- `addStrategy` = 同类器官**每件各触发一次**（可叠加）
- `addOnlyStrategy` = 同类器官**只触发一次**（唯一被动 / 光环 / 主动技）
- 合法事件 id 共 31 个（`$OrganEventIdType`）：`item_right_clicked / item_left_clicked / key_active / entity_do_damage / chest_cavity_update / food_eaten / block_broken / entity_be_hurt / player_enchant / entity_loot / chest_loot / organ_take_off / entity_tick / organ_take_on / entity_kill / entity_death / entity_be_interacted / entity_interact / decorate_chat / chat / iss_player_spell_cast / iss_entity_spell_cast / block_right_clicked / organ_add_status_effect / shield_block / exposure_frame_added / entity_fall / villager_update_special_prices / player_spawn_phantoms / player_dodge / trade_with_villager / player_respawned`

## 六、效果写法四范式

### 1) 属性加成 —— 只走 `chest_cavity_update` + customData

```js
function TelescopicArmChestCavityUpdate(customData, event, organItem, organIndex, slotType) {
    let blockReachUp = 1
    if (slotType == MachinaryLubricant) { blockReachUp = 4 }   // 槽位分支就写在这里
    customData.blockReach.addAttributeModifier(blockReachUp, 'addition', 'base')
}
```

customData 上可用的管理器：`attackDamage / maxHealth / armor / entityReach / blockReach`（本包另有 `attackSpeed` 等扩展）。
**禁止**在器官里直接 `addPermanentModifier` 改玩家属性 —— 那是给怪物用的。

### 2) 状态效果替换 —— `organ_add_status_effect`

```js
function CindariaUmbrellaOrganAddStatusEffect(customData, event, organItem, organIndex, slotType) {
    const effectInstance = event.effect
    if (effectInstance.getEffect().equals($MobEffects.POISON)) {
        event.setEffect(new $MobEffectInstance('minecraft:regeneration', 20 * 10))
    }
}
```

### 3) 计数器 / 层数 + HUD —— KV + OragnEffectModel

```js
let counter = GetCustomDataMap(chestCavity, 'blazeSpineCounter', 0)
if (counter <= 0) return
counter = counter - 1
SetCustomDataMap(chestCavity, 'blazeSpineCounter', counter)
if (counter > 0) {
    SetOrganEffect(chestCavity, new OragnEffectModel(organItem).setPriority(organIndex).setCustomText(counter.toFixed(0)))
} else {
    RemoveOrganEffect(chestCavity, 'kubejs:blaze_spine')
}
```

注意类名就是 `OragnEffectModel`（原库拼写错误，照抄即可别改）。
`organ_take_off` 里必须 `RemoveOrganEffect` 清 HUD。

### 4) 主动技 —— `key_active` + 物品冷却

```js
function BlazeSpineKeyActiveOnly(customData, event, organItem, organIndex, slotType) {
    const player = event.player
    const chestCavity = player.chestCavityInstance
    SetCustomDataMap(chestCavity, 'blazeSpineCounter', 1)
    SetOrganEffect(chestCavity, new OragnEffectModel(organItem).setPriority(organIndex).setCustomText('1'))
    player.addItemCooldown(organItem, 20 * 10)     // 冷却传 ItemStack，不传字符串
}
```

前置判定用 `OrganItemCoolDown(player, organItem)`（同样传 ItemStack）。

## 七、事件派发层写法（priority 999）

一个事件一个文件，三行：

```js
// priority: 999
const OrganEntityDoDamageEvent = new OrganEventModel('entity_do_damage')

function EntityDoDamage(event, customData) {
    const entity = event.source.actual          // 攻击类事件取「出手者」
    OrganEntityDoDamageEvent.run(entity, customData, [event])
}
```

- 攻击/受击类：`entity = event.source.actual`（生效目标）
- 其他类：`event.entity` 或 `event.player`
- `run(entity, customData, [event])` 的第三个参数是事件数组，框架按 priority 降序调用策略

## 八、util/organ.js 里现成的全局函数

| 函数 | 用途 |
|---|---|
| `GetEntityChestCavityInventory(entity)` | 直接返回 `entity.chestCavityInstance.inventory`（**不判空，传错实体就炸**） |
| `GetChestCavitySlotType(cc, index)` | `cc.getInventoryTypeData().getSlotType(index)` |
| `Get/Set/RemoveCustomDataMap(cc, key, v)` | 胸腔实例持久 KV（`cc.customDataMap`） |
| `GetCustomDataOrDefault(customData, key, d)` | 单次事件内的临时 KV |
| `OrganItemCoolDown(player, item)` | 主动技冷却判定（传 ItemStack） |
| `CommonDingNotice(level, player)` | 播放经验球音效当提示音 |
| `Set/Get/ResetPutridToxinsDamage(target, v)` | 把毒性伤害挂在**目标**的 persistentData 上（跨事件携带） |
| `Set/Get/ResetVitaToxins{Source,Type,Coe}(target, v)` | 同上，记录毒性来源 UUID / 属性类型 / 系数 |

**重要模式**：需要「跨多个事件记住是谁打的、记多久」时，本体不放在器官里，而是写到**目标的 persistentData**（`target.getPersistentData().putUUID/putFloat/putString`），再用 `Reset*` 清理。这比在攻击者身上存 KV 更稳（攻击者可能中途切胸腔）。

## 九、风格红线（从样例归纳）

1. 文件首行 `// priority: <数字>`，其后空一行再写 `RegistryOrgan`
2. 数据登记 → 函数定义 → 文件末尾 `RegistryOrganStrategy` 三段式，中间空一行
3. 每个函数都有完整 JSDoc（5 个参数一个不落），返回 `Internal.LivingEntity` 这类对象时补 `/**@type {...}*/`
4. 常量（UUID、槽位名、阈值）提到文件顶部 `const`；循环变量用 `let`
5. 槽位判断直接比字符串常量：`slotType == MachinaryLubricant`、`slotType == RevolutionFlame`
6. 数值不写死中文注释，说明写在 JSDoc 或代码旁 `//`
7. 物品 ID 全小写下划线、`kubejs:` 命名空间；贴图路径与 ID 镜像
